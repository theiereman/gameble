# Accessibility review: Le Grand Inventaire (2026-11-19)

Scope: EXPERIENCE.md "Le Grand Inventaire" (component table, Copy deck row, State Patterns rows, IA rows), DESIGN.md "Grand Inventaire", mock `mockups/grand-inventaire-layouts.html`, checked against "Accessibility Floor", "Focus after each step", and the patterns the feature reuses (Tabs and filters, See-more link, Filter zone, Card not owned, Pioneer row, Le Chattomètre, Tous les sets). Contrast was computed from the DESIGN.md YAML hex values. Items already tagged `[ASSUMPTION]` are only flagged when they carry an accessibility consequence.

## Findings

- **[high]** The pinned row loses focus and appears and disappears for screen readers. It is interactive ("following it jumps to their page and row") but is removed as soon as the viewer's row scrolls into view, which is exactly what following it does. Focus is then left on `body`, against the floor's rule that an update never leaves focus there. Because it comes and goes with the visual viewport, a screen-reader user reading with the virtual cursor (which does not scroll the page the same way) meets a node that flickers in and out of the accessibility tree. It is also unclear whether it is a second "Vous" row inside the list (EXPERIENCE.md, Classement des pionniers; DESIGN.md, Pinned row). *Fix:* render one link in the DOM, right after the period chips and outside the rows list, always present, named in words: "Votre position : 14e, 31 découvertes cette saison. Aller à votre rang". CSS pins it to the bottom only while the row is off screen. Otherwise it is visually hidden but stays in the tree, and it stays visible while it holds focus (`:focus-within`). Following it loads the page and moves focus to the viewer's row (`tabindex="-1"`), never leaves it on the vanished copy. It is not a live region and is never announced when it appears. Add the step to "Focus after each step".
- **[high]** The pinned row covers content and is not bounded by viewport height. A fixed bar at the bottom, above the 58px phone tab bar plus the safe area and under the sticky top bar, hides the last rows and any focused row beneath it (WCAG 2.4.11 Focus Not Obscured). At 200% zoom or more, or on a 360 × 740 phone in a short landscape window, the fixed bars take a large part of the viewport (Classement des pionniers; DESIGN.md, Pinned row). *Fix:* give the rows' container a bottom padding and `scroll-padding-bottom` equal to the pinned row's height plus the tab bar's. As for the market's Confier and sale bars, pin only from 560 CSS px of viewport height, and below that show the link in its flow position only.
- **[high]** Nothing in the spec covers keyboard or screen-reader use of scroll-loaded pagination ("Numbered pages that also load by scroll, fifty rows to a page"). Tous les sets has the same gap. Questions left open: whether loaded rows are announced; whether the numbered page links stay reachable or move ever further away; what happens to focus and URL when a page loads; how a reader gets back to rows above a page reached by the pinned row's jump. The Grid has 1 500 cards and the same problem (Classement des pionniers; Grid; Tous les sets). *Fix:* add one shared floor rule. The numbered pages are a `nav` named "Pages du classement" (or "Pages des cartes"), with real links that work without script, the current page `aria-current="page"`. Scroll-loading appends only on a pointer or touch scroll, never on Tab, so the page links stay reachable. A polite status line says "Lignes 51 à 100 chargées" or "Cartes 49 à 96 chargées", and focus never moves. The URL follows the page, so Back and a reload return to it. A page reached by a jump shows a "Page précédente" link above its first row.
- **[high]** "Focus after each step" has no entry for any step of this feature. Missing steps: following the pinned row, unfolding "Tout voir" in the Sets panel, switching a phone tab, following a rarity cell (the filtered grid), opening Set de la Confrérie or Classement des pionniers, and Back from a card detail to a card on a scroll-loaded grid page (the generic "Back → element that opened it" fails when that page is no longer rendered) (EXPERIENCE.md, Focus after each step). *Fix:* add rows. Pinned row followed: the viewer's row. "Tout voir" unfolded: stays on the control, now expanded. Phone tab chosen: stays on the tab (Tabs and filters). Rarity cell: the Cartes h2, with the chip shown pressed. Set de la Confrérie opened: its h1 (as Set album). Back from it: the set row that opened it, with the list unfolded again if it was. Classement opened: its h1. Back from a card detail: the card, its page restored from the URL and the CARTES tab restored on the phone.
- **[medium]** The phone tabs contradict the house rule in the mock. Tabs and filters says `aria-pressed` in a `role="group"`, never `role="tab"`, but the mock's layout C uses `role="tablist"` and `aria-selected`. The spec also says nothing about the inactive views being hidden from assistive technology, or about naming the group (EXPERIENCE.md, Layout; mock, layout C). *Fix:* keep the house pattern. Use three buttons with `aria-pressed` in a group named "Vue du Grand Inventaire". Inactive views carry `hidden`, so they are out of the tree and out of tab order. The chosen view is in the URL, so Back restores it. Correct the mock so builders do not copy `role="tablist"`.
- **[medium]** The phone tab "SETS" sits on the same screen as the app tab bar's "SETS" link, which is a different destination. A screen-reader user who lists buttons and links, and a voice-control user who says "SETS", get two targets with the same name (Layout, phone tabs; DESIGN.md, Phone tab bar). *Fix:* name the view switch differently in its accessible name, for example `aria-label` "Sets de la Confrérie" with the visible text kept, so the accessible name still starts with the visible text. Or label the group so that "SETS, Vue du Grand Inventaire" reads apart.
- **[medium]** Card accessible names leave out what the floor requires. "Card text order" says a card's name always holds the full title, the studio, the year and the number. The Grand Inventaire names hold only game, rarity and pioneer ("Outer Wilds, Épique, découverte par Léa"). The copy badge's spoken text "37 exemplaires dans la Confrérie" is given but placed nowhere: an `aria-label` on a decorative span inside the card link is not read (Found card; Card to discover; Copy deck). *Fix:* name a found card "Outer Wilds, Mobius Digital, 2019, n° 042, Épique, découverte par Léa, 37 exemplaires dans la Confrérie", with the badge's text appended to the card link's name and the badge itself `aria-hidden`. Add the zero and one forms to the Copy deck: "aucun exemplaire dans la Confrérie" and "1 exemplaire dans la Confrérie". The French zero plural key is needed (Known pitfalls). Either do this, or record an explicit exemption from "Card text order" for this grid.
- **[medium]** A screen reader hears each card's words twice. The spec does not say how the card link and the caption under it relate. If the caption (game name, pioneer link, "À découvrir") sits outside a link that already names everything, a card to discover reads "Tunic, Rare, à découvrir, lien · Tunic · À découvrir", and a found card repeats both the game and the pioneer (Found card; Card to discover; DESIGN.md, Grid cards). *Fix:* as with trade suggestions, hide the caption's game name and "À découvrir" from assistive technology, since the link's name holds them. Keep the pioneer link exposed as a separate, following tab stop, never nested in the card link. A screen reader then hears "Tunic, …, Rare, à découvrir, lien" once, and for a found card the card link, then "Léa, lien". The lock stays hidden (floor). State that "non possédée" is not appended here, since the viewer's holdings play no part.
- **[medium]** The "VOUS" badge and the "Vous" pioneer name may be read twice, or carried by gold alone. The spec does not say what the card's name holds for the viewer's own discovery. A viewer in a board's top 3 is "highlighted in place", which suggests colour alone (Found card; Pioneer boards; DESIGN.md, Panels). *Fix:* the card's name reads "…, découverte par vous", with the "VOUS" badge `aria-hidden`. In the top 3, the viewer's row prints "Vous" (or the name followed by visible "(vous)"), never just the accent colour.
- **[medium]** The pioneer boards' list semantics contradict the ranks. In the mock the "Vous" row is a fourth `<li>` of the `<ol>`, so a screen reader says "4 sur 4" before "14e". The rows give a bare count with no unit ("Léa 9"). The same applies to Classement des pionniers ("rank, name, count") (Pioneer boards; Classement des pionniers; mock). *Fix:* keep the `<ol>` to the ranked rows. Put the "Vous" row in its own element after the list, named "Votre rang : 14e, 1 découverte cette semaine". Give counts a unit through visually hidden text ("9 découvertes"). Or make the full ranking a table with column headers Rang, Joueur and Découvertes, like the Chattomètre's full screen.
- **[medium]** The two boards' "Voir tout le classement" links have the same accessible name and lead to different periods. The See-more rule requires each name to start with its visible text and name the destination (Pioneer boards; Copy deck). *Fix:* name them "Voir tout le classement, pionniers de la semaine" and "Voir tout le classement, pionniers de la saison", and add both to the Copy deck.
- **[medium]** The Sets panel's "Tout voir" unfolds the list in place, so it is a disclosure, not a navigation. The See-more link pattern assumes a link to another screen, and no expanded state or focus is defined (Sets panel). *Fix:* make it a button styled as the See-more link (`ButtonComponent`, `variant: :link`) with `aria-expanded` and `aria-controls`. Focus stays on it. After unfolding, its name reads "Tout voir, sets de la Confrérie" (or "Réduire"). Each set row is a link named "Roguelike, 58 sur 62 découvertes" or "…, entièrement découvert".
- **[medium]** Slash counts and abbreviations have no spoken form. Examples: "1 204 / 1 500 cartes", the rarity cells' "found / total", the set rows' found / total, the collection tile's "1 204 / 1 500 découvertes", "il y a 12 min", and "x37". The floor's rule for reading slashes as "sur" is scoped to Duels and the back picker (Head; Sets panel; Collection tile; Hub panel; Copy deck). *Fix:* use the same visually hidden text: "1 204 sur 1 500", "il y a 12 minutes" (in a `<time>` element), and the badge text above. Write thousands with a narrow no-break space (U+202F) so "1 204" is not read as two numbers. Better still, promote the slash rule to a general floor line.
- **[medium]** The gauges and rarity cells have no defined accessible form. The floor says gauges are progress bars with a text value, but nothing names the head gauge, the hub gauge or the Set de la Confrérie bar, and nothing gives a rarity cell's link name. The cell's colour is only a 4px edge, which is fine, but the mock prints the rarity name in rarity colour inside a link, against "Rarity-coloured text is never interactive" (Head; Hub panel; DESIGN.md, Head; mock `.rar span`). *Fix:* make each gauge a `progress` element (or `role="progressbar"`) named "Cartes découvertes par la Confrérie", with `aria-valuetext` "1 204 sur 1 500". Name each rarity cell link "Épique : 120 sur 300 découvertes. Voir les cartes épiques", with its name text in `{colors.text-bright}` and the colour on the edge only. Correct the mock.
- **[medium]** The Classement des pionniers period chips do not say what is announced when the period changes. The rank and rows change entirely, and the pinned row's figures change with them (Classement des pionniers). *Fix:* follow the Chattomètre panel. The chips sit outside the replaced region and focus stays on the chosen chip. A polite status line, empty at load, says "Saison : vous êtes 23e, 31 découvertes" (or the no-discovery line, or for a visitor only the period).
- **[low]** No heading is given for the hub panel or for Classement des pionniers. The floor wants one h1 per screen. The hub panel's title "Le Grand Inventaire" is not given a heading level, so a screen-reader user who jumps by heading through the hub skips it (Hub panel; Classement des pionniers). *Fix:* the hub panel is a `<section>` headed by an h2 "Le Grand Inventaire", with its See-more link inside that section in the DOM (See-more rule). Classement des pionniers has the h1 "Classement des pionniers".
- **[low]** Capitalised copy is written in capitals in the Copy deck: "VOUS", "CARTES", "PIONNIERS", "DÉCOUVERTES", "À DÉCOUVRIR", "ENTIÈREMENT DÉCOUVERT". Some screen readers spell short words in capitals, which the floor already avoids for duel labels (Copy deck). *Fix:* write them in sentence case in `fr.yml` and `en.yml` and capitalise them with CSS.
- **[low]** Several items in the mock break the floor: the "VOUS" badge is set at 9px (the floor sets 10px as the minimum for meaningful text); the phone tabs are 40px tall (44 × 44 is the touch minimum); the panel titles are gold, though DESIGN.md says "never gold"; "VOUS" is CSS `content`, which some screen readers skip (mock, `.cd.me .face::after`, `.tabs button`, `.panel h3`). *Fix:* correct the mock, or note under it that the spines win on these four points, so builders do not copy them.
- **[low]** The phone touch targets are not stated for this screen's own controls. The rarity cells (two to a row), the set rows, the board rows' name links, the pace line's inline links, the pinned row and the grid's pioneer links under each card (11px text, one line) need the 44 × 44 hit area and 8px gap from the floor (DESIGN.md, Head; Grid cards). *Fix:* add one line to DESIGN.md, Grand Inventaire: every row, cell and the pinned row is at least 44px tall on the phone. A pioneer link under a card gets a 44px-tall hit area through padding, without overlapping the card link above it. The inline links in the pace and hub lines are an accepted exception for inline text (WCAG 2.5.8 exempts them) only if the same destinations can also be reached through larger targets.
- **[low]** Reduced motion is not addressed. If the pinned row slides in or out, the "Tout voir" list unfolds with motion, the gauges fill on load, or scroll-loaded rows fade in, nothing says whether "ANIMATIONS RÉDUITES" stops it (Layout; Classement des pionniers; Motion). *Fix:* state that the screen has no motion beyond these, and that each becomes a plain swap with "ANIMATIONS RÉDUITES" and with `prefers-reduced-motion`.
- **[low]** For the visitor, the sign-in prompt and button appear "once per screen, under the boards". On the phone they then appear only in the PIONNIERS view, while the CARTES view (the default) shows cards to discover with no way to join. This is not a barrier, but it is a lost cue (Visitor). *Fix:* say which view holds the prompt on the phone. The Steam button follows the existing "Links and sign-in" naming.

## Checked and fine

- Contrast of the named colours, computed from the YAML. `{colors.muted}` is 6.0:1 on a panel and 6.6:1 on the ground (the name of a card to discover); `{colors.gold}` is 10.8:1 on a panel and 11.8:1 on the ground; `{colors.accent}` (the "Vous" row) is 8.7:1 on a panel; `{colors.lime}` (the pace line's counts) is 10.6:1 on the ground. `{components.control-border.css}` around the pinned row is 3.2:1 on a panel. The gold "VOUS" badge's own fill with dark text clears 4.5:1 whatever the art behind it. The dashed `{colors.line-soft}` rule is decoration.
- The rarity cells are not colour alone: the name is printed in each cell. Names with and without links follow the Pioneer row rule. The read-on-load pace line needs no live region.
- Heading structure on the main screen: one h1, with h2s for Sets, both boards and Cartes. Set de la Confrérie inherits the Set album's h1 and back rules.
