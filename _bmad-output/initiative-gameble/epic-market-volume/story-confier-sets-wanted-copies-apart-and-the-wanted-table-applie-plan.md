## Intent

**Problem:** Confier entrusts every ticked copy, even one another player wants; `ApplyWantedChoices` (entry 8) exists but no screen sets wanted copies apart or lets the seller sell, auction or entrust each one in one validation. Its `stamp_not_covered` and `start_below_minimum` refusals cannot be rendered: their keys need `%{amount}`/`%{rarity}` that `Refused(line:, code:)` does not carry.

**Approach:** Step 1: Confier's cells carry "DEMANDÉE · n", the recap sets one copy per seeker apart (client preview, server recomputes), the rest is entrusted by `EntrustCards` and the create redirects to step 2 at its own address carrying the set-apart selection in the URL. Step 2 (`Market::WantedChoicesController`): a full-width table drawn by a new `Game::Market::WantedTable` query, one radio group per line drawn by a new `SegmentedComponent`, prefilled and totalled by a TS state module, submitting to `ApplyWantedChoices` (or `EntrustCards` for TOUT CONFIER QUAND MÊME), its refusals redrawn inline, its success a result panel. `Refused` gains `amount:` to settle the deferred render gap.

## Boundaries & Constraints

**Always:** writes only through `EntrustCards` and `ApplyWantedChoices`; GETs write nothing; every new action has a Pundit policy; refs (`slug:season`), order tokens, listing tokens and the settings token only in HTML/URLs/JSON, never ids; seekers from `WantedCopies` (never a second wanted formula), orders from `EligibleOrders`; the table's order assignment is the operation's greedy (`EligibleOrders.call(cs, except:, now:).where.not(id: assigned)` in table order, each order once across lines); the form posts lines in table order; server-rendered markup, controllers clone `<template>`s and write text/attributes/`hidden` only; one root controller with its state module `app/frontend/lib/wanted_table.ts`; no `style` attributes; every string in `en.yml` and `fr.yml` (French as the Copy deck draws it, English beside it, plural keys with `zero`, U+202F before `:` `;` `?` `!` in French); files ≤ 400 lines (Ruby, TS), ≤ 500 (CSS); no planning ids; comments only for external constraints; `npm run format:check` and `npm run lint:css` pass.

**Never:** a migration; changing `WantedCounts`, `EligibleOrders`, `RefreshWanted`; changing `ApplyWantedChoices`' behaviour beyond `Refused#amount`; the quick JSON entrust path (`create` with `Accept: application/json`, the card detail's quick action) — it keeps entrusting everything; restyling other screens with `SegmentedComponent`; client-side field validation that blocks submit (fields are checked on submit by the server); session or DB state for the set-apart copies.

**Ticket `unknown`, settled by EXPERIENCE.md (follow, note in Implementation Notes):** no paging; a line whose CONFIER would not fit the cap left is prefilled ENCHÈRES at the average, or the minimum with none; stamps paid from the same validation's proceeds (the operation already nets them); the reopened step shows the copies still set apart, else the market; the phone dock holds the total, VALIDER and TOUT CONFIER QUAND MÊME.

## Implementation Notes

- Settled by EXPERIENCE.md, followed as written: no paging; a no-order line whose CONFIER would not fit the cap left (walked in table order) prefills ENCHÈRES at the average or the minimum; stamps are netted by the operation; the reopened step redraws the copies still set apart, else 303 to the market; the phone dock keeps the total, VALIDER and TOUT CONFIER QUAND MÊME.
- Step-1 counts ("MISES DE CÔTÉ · n", "CHOISIR POUR LES n…", the status suffix) count set-apart copies; step 2 counts lines (choices).
- Refusal focus is driven by the root controller on connect (`focus` value: the heading on GET, the first changed group's checked radio or the first invalid field after a 422, else the dock line) rather than a `gameble-focus` stream action, because the prefill of a changed line only exists after the controller connects; the success result still uses `gameble-focus`.
- `stamp_not_covered` carries the total auction-stamp shortfall of the validation (every stamp minus the funds), the amount the dock line names.
- Enter in any field of the table is held: the form's first submit button is TOUT CONFIER QUAND MÊME.
- Order tokens are always posted with their line; the operation reads them only for the order choice.
- Known limit: two editions of one card in the same table share its orders; if the earlier line is not sold to its drawn order, the later line's drawn (second-best) order no longer matches the operation's greedy and the validation is refused as `best_order_changed`.

## Design Notes

- The set-apart copies live in the step's URL (`selection`, Confier's `ref=copies` pairs): reopening the address redraws what is still free, a reload after success finds nothing and lands on the market, and no state is stored.
- The client previews the set-apart split and the prefill; the server recomputes the split at create and is the truth. The prefill is client-only: the server renders posted choices back on a refusal and flags changed lines, the root prefills every line with no posted choice.
