### Lens findings (boundaries only; narrowed scope)

Lenses run inline: adversarial, edge-case, verification-gap. Boundaries read: the root switch with the rate limit and the read-only role; the SEO noindex changes; the lamp, the motion switch and reduced motion; the gauge and the moving cards layer.

**The root switch, the rate limit and the read-only role**

- **F1 (edge-case, fix). A visitor request for the root with `Accept: */*` is redirected to the root itself.** `PagesController#visitor_landing?` is `current_player.nil? && request.format.html?` (`pages_controller.rb:57-58`). For `Accept: */*`, `request.format` is the `*/*` type and `html?` is false (observed through `ActionDispatch::Request`), so `home` falls through to `authorize :page, :play?`, which a visitor fails, and `refuse_in_locale` redirects a visitor to `home_path` with 303 (`application_controller.rb:153-157`): the same address. Observed: `GET /en` with `Accept: */*` answers `303` with `Location: /en`, for the user agents Discordbot, facebookexternalhit, Twitterbot, Googlebot and curl alike (the header is what decides). `Accept: text/html`, a browser-like list, and no Accept header answer 200 with the landing. `curl https://gameble.net/en`, an uptime probe or any client that sends `*/*` loops. Whether the real link-preview and search crawlers send `*/*` is not known from the repo (open question). The landing's tests only send the default browser-like Accept (`test/controllers/landing_page_test.rb:40-66`, `:310`). Disposition: fix before the production release (action item 1).
- **F2 (edge-case, fix). A visitor request for the root with `Accept: text/vnd.turbo-stream.html` raises a 500.** The type's `html?` is true (it contains "html"; observed), so `show_landing` runs and `render "landings/show"` raises `ActionView::MissingTemplate` for the format `turbo_stream` (observed; the test framework reports "Neutered Exception ActionView::MissingTemplate"). `Accept: application/json`, `text/plain` and `image/*` are refused with 401 as designed. Rare in practice (Turbo sends that Accept on form submissions), but it is an unhandled path on the epic's main entry point. Same fix as F1. Disposition: fix (action item 1).
- **F3 (adversarial and edge-case, defer; the author decides). The root counts against the public-read throttle for signed-in players too.** `PublicReadThrottle.public_read?` returns true when the page segment is blank (`config/initializers/rack_attack.rb:34`), which includes every hub request (`/fr`, `/en`), and Rack::Attack cannot see the session. Observed: a signed-in player's 121st `GET /en` from one address within a minute gets **429 with a plain-text body** ("Too many pages read in a minute. Try again in a moment.", content type `text/plain`), not a page; after the 120 allowed reads the same player's `GET /en/settings` still answers 200, so only the shared-pages counter bites. Players behind one address (a household, a school, a carrier NAT) share the 120 per minute. This is the open deferral of 20.15 and of the sweep ("settle by measuring hub GETs per player", `story-refactor-sweep-plan.md`, frontmatter `deferred`); this run confirms the mechanism, not the real traffic. The existing tests assert the root is counted (`test/integration/rate_limit_test.rb:249`) but none requests it 121 times, and none looks at what a player sees. Disposition: defer to a measured decision (action item 2).
- **F8 (adversarial, defer). `readable` hides a write attempted on a GET.** `PagesController#readable` rescues `ActiveRecord::ActiveRecordError` (`pages_controller.rb:72-78`); `ActiveRecord::ReadOnlyError` is a subclass (checked), and GETs run with writes prevented. A landing query that started to write would show a dash and log "landing block unreadable" instead of failing the `ReadOnlyRequestsTest` family, and the landing is not among the routes that suite probes (`test/controllers/read_only_requests_test.rb` uses its own probe controller and only routes `pages#home` for the helper). Low. Disposition: defer; narrow the rescue or re-raise `ReadOnlyError` (action item 8).
- **F15 (verification gap, defer). The landing's per-locale caches are never exercised at request level.** `config/environments/test.rb:23` sets the null store, so the controller tests cannot see a cache hit; `test/packs/game/landing_queries_test.rb` covers the queries on a memory store. Done when 1 and R2 ("each data block is cached per locale") therefore rest on the query-level tests plus the plans' own deferrals (20.5: "No request-level test shows the landing itself hits the cache"). The Solid Cache write inside a GET relies on `SolidCache::Record` not being an `ApplicationRecord`, so it escapes `prevent_writes`; plan 20.2's triage log reasons the same way, and production's cache store is `:solid_cache_store`, but no test runs the real store. Disposition: accept as recorded by the sweep; revisit if the cache moves.
- **Checked, clean.** The shared URL carries two pages, so a shared cache would be dangerous: observed `Cache-Control: max-age=0, private, must-revalidate` for both the visitor's landing and the player's hub, no `Vary`, no `Set-Cookie` on the landing GET. A signed-in player at `/en` gets the hub (`landing_page_test.rb:193`); `/fr/landing` redirects permanently to the root (`config/routes.rb:16`, `landing_page_test.rb:203`); sign-out and account deletion redirect to `home_path` (`sessions_controller.rb:54`, `accounts_controller.rb:18`; `sessions_controller_test.rb:341`).
